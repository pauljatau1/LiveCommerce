# Email audit

Signup/verification/resend and buyer/seller forgot-password mail use the new shared template by default. The current v2 buyer registration auto-verifies email and sends no signup email; this behavior is preserved. The seller welcome email uses the shared layout. Old auth layouts and HTML files are retained for rollback, with `CLASSIC_EMAIL_TEMPLATES` off by default.

The following sending locations are retained. Non-auth emails keep their existing business wording, layout, attachments and recipients because this request only redesigns signup and password recovery. Buyer/seller links in those layouts were audited and moved to app URL helpers. This is an inventory, not a claim that every layout was redesigned.

Retained template files: `account-deletion-email.html`, `account-deletion-confirmation-email.html`, `business-verification-email.html`, `seller-admin-notification-email.html`, `seller-verification-email.html`, `smileid-callback-verification-email.html`, `user-report-notification-email.html` and `shipmentEmailTemplates.js` handle deletion, compliance, internal operations, identity verification, reports or shipments rather than signup/reset. Their contents and provider behavior were preserved. `register-email.html`, `resend-otp-email.html`, `password-reset-email.html` and `seller-welcome-email.html` remain as legacy auth layouts; the relevant active paths use the shared template by default. The generic unused `utils/emailService.sendPasswordResetEmail(email, token)` is retained; active buyer/seller reset routes use the shared template.

The internal admin order link in `modules/orderv2/helpers/order.helper.js` remains an admin URL: neither buyer nor seller app is its destination. API host detection, analytics API URLs and shipment webhook callbacks are backend endpoints and retain their own configuration. Verified `support@auqli.com` sender/contact mailboxes remain email addresses, not frontend links.
