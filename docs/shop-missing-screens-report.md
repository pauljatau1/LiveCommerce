## Differences from the PNGs

- **W7 remains Paystack's secure popup.** The existing `charge_authorization` paused response supplies an `access_code`, consumed by `resumeTransaction`. It does not supply the direct charge API's `send_otp` challenge. An app-owned Confirm/Send-again form would not be able to complete that transaction correctly. No invented OTP/resend endpoint and no change to the functioning payment path were introduced.
- Use existing type and colour tokens, including the existing danger colour for red error fields. Popular chips keep 44px tap targets; saved-card text wraps on narrow phones instead of overflowing.
- The area directory is authoritative, so actual search result counts depend on its current rows (for example `vi` also matches Computer Village). No screenshot-specific results were hard-coded.
- Profile keeps Set default for non-default addresses. The existing request/token expiry and password rules remain enforced by the server.
- The receipt says "Your bid is in" only after the buyer's `bid_placed` acknowledgement, never simply because a top-up arrived.
- Buyer and studio area **search logic** remains identical. The previous byte-for-byte UI equality test was narrowed to search logic because the studio PNG updates are in branch 3.
